## Step 15: mock S/4HANA (9 Nov 2026)
Written with Claude Code. This is a simulated S/4HANA, not a real SAP system.
- srv/external/API_SALES_ORDER_SRV.js: mock implementation of SAP's Sales Order API. CAP runs it automatically ("mocking API_SALES_ORDER_SRV") at /odata/v4/api-sales-order-srv inside the Project 2 server.
- Invented master data matching the sample bookings: 10 customers (CUST12345 ...) and 10 trip products (TRIPITALY2024 ...) with a price per traveller.
- SAP-like checks: sales area must be OR / 1010 / 10 / 00; customer and product must exist; customer reference required; at least one item; quantity a whole number of at least 1.
- On success it assigns the next number (5000001, 5000002, ...), item numbers 10, 20, ..., net amounts and the total.
- srv/external/data: two earlier orders (5000001 for BRQ10006, 5000002) so the system does not start empty.

Tests (7 of 7 passed):

2. Valid order (CUST67890, TRIPSPAIN2024 x 2): created with the next number, total 1,500 EUR, item 10 stored.
3. Unknown customer: refused (400) "Sold-to party CUST00000 does not exist."
4. Unknown product: refused (400).
5. No items: refused (400).
6. Wrong sales organization: refused (400).
7. Order count correct afterwards.

Notes:

- Limitation: the mock runs inside the same server as the app, so no network call happens. A real S/4HANA would be called over the network with OData V2.

## Deployment to SAP BTP (9 Nov 2026)
Problem found before deploying: the imported SAP API is marked external with no storage, so the CAP mock had no tables in SAP HANA Cloud and would not run on BTP. Also, the sample requests were in test/data, which is not deployed.

Change (written with Claude Code):
- db/mock-s4.cds: own tables for the simulated S/4HANA (namespace mocks4) with SAP's field names and types (a subset of A_SalesOrder and A_SalesOrderItem); items are a composition, so an order is created together with its items and can be read with $expand=to_Item (this fixes the earlier limitation).
- srv/mock-s4-service.cds and .js: MockS4Service at /odata/v4/mock-s4 with the same checks as before. The old srv/external/API_SALES_ORDER_SRV.js was removed; the official SAP model (API_SALES_ORDER_SRV.cds and .edmx) stays as the reference and for a real S/4HANA.
- srv/s4-sales-order.js: uses the real S/4HANA if credentials for API_SALES_ORDER_SRV are configured, otherwise MockS4Service. The same code path runs locally and on BTP.
- Sample data moved from test/data to db/data so it is deployed (redeploying resets the sample rows).
- Local check after the change: 7 of 7 Step 17 tests passed; order with items returned by $expand.

Deployment: cds add hana, xsuaa, approuter, html5-repo, mta; sap.cloud added to the app manifest; router welcome page /travelorderaiintake/index.html; package-lock.json created in the app folder; backend memory 256 MB. OpenAI key set with cf set-env from the private .env (not printed, not in any deployed file).

Checks on BTP:
